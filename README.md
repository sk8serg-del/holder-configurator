# Конфигуратор подложкодержателей

Веб-страница для заказа подложкодержателей: технолог выбирает диск и контрольные
отверстия из каталога, задаёт детали (круглые, прямоугольные, с фаской) и зазоры —
страница автоматически раскладывает детали, показывает результат и формирует:

- **CSV координат** — по нему правило iLogic строит отверстия в Inventor;
- **PDF-отчёт** — через печать браузера;
- **запись в Google Таблицу** — учёт заказов (через Google Apps Script).

Всё считается в браузере, сервер не нужен. Хостинг — любой статический
(GitHub Pages, Cloudflare Pages).

## Запуск локально

Просто открыть `index.html` в браузере. Сборка не требуется.

Тесты раскладки (проверяют, что все зазоры соблюдены):

```
node test/test-packer.js
```

Smoke-тест всей страницы (форма → раскладка → CSV → отчёт; требует один раз
`npm install jsdom`):

```
node test/test-page.js
```

## Сборка в один файл

Для отправки страницы одним файлом (почта, флешка, хостинг без папок) — CSS
и все скрипты инлайнятся прямо в HTML:

```
node tools/build-single-file.js
```

Результат — `dist/holder-configurator.html`, ничего кроме node не требуется.
Файл не хранится в репозитории (генерируется), пересобирайте заново после
любых правок в `index.html`, `css/` или `js/` — источник правды всегда там.

## Как добавить/изменить подложку

Все подложки — в файле [`js/catalog.js`](js/catalog.js). Одна запись = один диск:

```js
{
  id: "disc-100",                 // уникальный код
  name: "Диск Ø100",              // название для заказчика
  diameter: 100,                  // мм
  controlVariants: [              // варианты контрольных отверстий
    { id: "none", name: "Без контрольных отверстий", holes: [] },
    { id: "3xD4", name: "3 × Ø4 на R40",
      holes: [ { x: 40, y: 0, d: 4, name: "R40 / 0°" }, ... ] }
  ],
  defaults: { partPart: 2, partEdge: 5, partControl: 3 }  // зазоры по умолчанию, мм
}
```

У контрольного отверстия `x, y` — позиция от центра (фиксирована), `d` — диаметр
**по умолчанию**, `name` — подпись в форме. Наличие каждого отверстия (галочка)
и его фактический диаметр технолог задаёт на странице.

⚠ Сейчас в каталоге **условные примеры** — заменить на реальные размеры.

## Настройка записи в Google Таблицу (~5 минут)

1. Откройте учётную Google Таблицу → Расширения → Apps Script.
2. Вставьте содержимое [`apps-script/Code.gs`](apps-script/Code.gs).
3. «Развернуть» → «Новое развёртывание» → «Веб-приложение»:
   выполнять **от вашего имени**, доступ — **«Все»**.
4. Полученный URL (`https://script.google.com/macros/s/…/exec`) вставьте в
   [`js/sheets.js`](js/sheets.js) → `HC.APPS_SCRIPT_URL`.

Лист «Заказы» создастся автоматически при первом заказе. При обновлении кода
скрипта нужно создавать **новое развёртывание** (или обновлять текущее).

## Inventor: правило iLogic

Файл [`inventor/HolderFromCSV.iLogicVb`](inventor/HolderFromCSV.iLogicVb).

1. В Inventor: Управление → iLogic → создать правило (удобнее — внешнее правило),
   вставить код целиком.
2. Открыть болванку диска. Требования: центр диска в начале координат,
   ось диска — Z (эскиз основания на плоскости XY).
3. Запустить правило → выбрать CSV → указать, строить ли контрольные отверстия
   (если они уже есть в болванке — «Нет»).

Правило (формат CSV **v3**, обратно совместим с v2) строит реальные карманы:
**посадку** (глухой вырез на глубину `depth` от верхней грани диска), **паз
под пинцет** (настоящей дугой SketchArc, не полилинией — гладкий стадион, на
ту же глубину), **зону напыления CA** (сквозной вырез меньшего контура на дне
посадки) и **метку-ориентир** — маленькую коническую зенковку (по умолчанию
Ø2мм, угол 90°) у каждой ДЕТАЛИ с пазом (не у контрольных отверстий), всегда
с одной и той же стороны паза, в 2мм от посадки и в 2мм от паза — нужна, чтобы
отличать похожие по размеру детали и метить ориентацию у форм, где это важно.
Поддерживаются круг, прямоугольник, фаска и овал. Посадки/пазы группируются по
глубине (по одному вырезу на глубину), зона напыления и метки — по одному
сквозному/коническому резу на всё. Тело диска правило не строит; при
несовпадении диаметра болванки и CSV выводится предупреждение. Глубина реза
от верхней грани (Z макс) вниз (−Z).

⚠️ Знак угла сужения конуса метки (`TaperAngle`) не проверен на реальном
Inventor — при первом запуске убедитесь, что зенковки получаются сходящимися
внутрь, а не расширяющимися проёмами; если наоборот, поменяйте знак в
`CutCountersink` (в конце `HolderFromCSV.iLogicVb`).

Плюс обновляет **гравировку** (Emboss): номер (поле «Номер», вводится вручную)
и название подложкодержателя — «Название» формируется **автоматически** по
составу деталей после раскладки (`d{d} (D{seatD}/CA{ca}) N{кол-во}` для круга,
`{w}×{h}(×{фаска}) N{кол-во}` для прямоугольника/овала/фаски; несколько типов
деталей — через «/»; не длиннее 42 символов, гравировка) — оба поля пишутся в
геометрический текст (Sketch Text) внутри эскизов **`Sketch9`** (вложен в Emboss
`PartNumber`) и **`Sketch10`**
(вложен в Emboss `PartDimensions`) — сами Emboss-фичи и эскизы должны уже
существовать в болванке (правило их не создаёт, только меняет текст через
`TextBox.Text`). Имена эскизов зашиты строками в конце `HolderFromCSV.iLogicVb` —
если переименуете их в Inventor, поправьте и в правиле. Если гравировка не
найдена/не обновилась — отверстия всё равно построятся, проблема попадёт в
итоговое сообщение отдельной строкой.

## Inventor → каталог: выгрузка реальных отверстий

Чтобы перенести в конфигуратор реальную геометрию болванки (контрольные и
крепёжные отверстия) вместо условных примеров — без ручного обмера чертежа:

1. Файл [`inventor/DumpHoles.iLogicVb`](inventor/DumpHoles.iLogicVb) — правило
   iLogic. Открыть в Inventor деталь с готовыми отверстиями (та же система
   координат, что и для правила выше — центр в начале координат, ось Z),
   запустить правило → сохранится `<имя-детали>-holes.csv`.
   Разбирает Hole-элементы (команда «Отверстие»), круглые вырезы Extrude/Cut
   (эскиз-окружность) и фигурные вырезы Extrude/Cut (контур из линий/дуг —
   напр. `Mountings`; строка `contour` со списком точек). Координаты через
   `SketchToModelSpace`, плоскость эскиза любая. Fillet/Chamfer (фаска) и
   Emboss (гравировка) не обрабатываются — гравировку вносим вручную.
   Диаметр/координаты читаются надёжно; зенковка/резьба/тип — по возможности
   (для резьбовых Ø часто = 0, задаётся вручную).
2. `node tools/import-holes-csv.js <имя-детали>-holes.csv --disc 298` —
   печатает готовый фрагмент записи диска (`blankDiameter`, `fixtures`,
   `holes`). Строки с общим центром сливаются: посадка-counterbore →
   `seatD`+`depth`, самый большой сквозной вырез меньше посадки → `apertureCA`.
   `--disc <Ø>` задаёт полезную зону: отверстия ВНУТРИ неё → контрольные
   (`controlVariants[].holes`), круглый крепёж на фланце → `fixtures.holes`
   (группами по Ø), фигурные контуры → `fixtures.cutouts`; крупные
   окружности-границы дают `blankDiameter`. Резьбовые без Ø выводятся
   отдельным списком координат. Вставить в запись диска, проверить
   `slotAvailable`, названия, стандартный `d`, толщину; канавки и гравировку
   (их дампер не даёт) внести вручную.

### Самостоятельная загрузка подложки на странице

Кроме CLI, ту же выгрузку можно загрузить прямо на странице — раздел
«Подложка» → «＋ Загрузить свою подложку (CSV из Inventor)»: выбрать CSV,
указать Ø полезной зоны, толщину и название → диск добавится в список и
сохранится в браузере (localStorage), без правок кода. Логика общая с CLI —
`HC.holderImport.buildDiscEntry` в [`js/holder-import.js`](js/holder-import.js).
Ограничение: тип отверстия (зенковка/паз/сторона) выгрузка не различает —
такие подложки грузятся с обычными сквозными/посадочными отверстиями, тонкая
настройка (паз, зенковка, стороны, гравировка) — по-прежнему в `js/catalog.js`.

## Формат CSV

Разделитель `;`, десятичная точка `.`, единицы — мм (углы — градусы), координаты
от центра диска. Формат **v3**: по каждой детали/КО — строка с посадкой, зоной
напыления, пазом, глубиной и меткой-ориентиром. Поля круга: `d/seatD/caDia`;
прямоуг./фаска/овал: `w/h/chamfer/rot/seatGap/caInset`; общие:
`slot/slotAngle/slotL/slotW/depth/markX/markY` (`markX`/`markY` — только у
деталей с пазом, пусто у контрольных отверстий и у деталей без паза; строка
`mark;{Ø};{угол}` задаёт диаметр/угол зенковки для всех меток разом).

```
holder-csv;3
order;PD-20260710-1530;2026-07-10T15:30:00.000Z;Иванов;НИИ
disc;disc-100;Диск Ø100;100;6
holder;;
clearances;2;5;3
mark;2;90
columns;kind;type;cx;cy;d;w;h;chamfer;rot;seatD;caDia;seatGap;caInset;slot;slotAngle;slotL;slotW;depth;markX;markY
control;circle;40;0;4;;;;;4.2;2.7;;;0;;;;4.5;;
part;circle;0;0;25.4;;;;;25.6;24.1;;;1;0;30.6;9;4.5;13.585;5.873
part;rect;20;10;;20;10;;0;;;0.15;0.6;0;;;;4.5;;
part;oval;-30;0;;24;12;;0;;;0.15;0.6;1;0;29.3;9;4.5;-17.143;5.91
```


## Интеграция с Odoo (задел)

Отправка заказа изолирована в [`js/sheets.js`](js/sheets.js) за функцией
`HC.submitOrder(payload)`. Варианты переноса:

1. **iframe** — страница сайта Odoo со вставкой этой страницы; без переделок.
2. **Нативный модуль** — вся логика (каталог, раскладчик, рендер, экспорт) —
   чистый JS без сборки, переносится как статические ассеты модуля Odoo;
   заменяется только `submitOrder` (POST в контроллер Odoo, который создаёт
   заявку/quotation). Можно параллельно продолжать писать в Google Таблицу.
